# Case Studies

Additional case studies may be added to this repo at a future time.

A **case study** applies this workflow to a real project for a real
organization, from Feasibility through Maintenance. Each one would live in its
own repository and get an e-number (`e01`, `e02`, and so on) listed here.
Inside a case study's repository, files use the same c and d numbers as the
prompts and templates they came from, so `d03-01` is always that project's
Product Requirements Document (PRD). E-numbers are never reused.

Until then, the [sample](../samples/README.md) shows every step's
documents for a made-up project, BeautifulBeachPark's volunteer app.
